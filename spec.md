# Designity — технические требования

## 1. Назначение

Designity — веб-сервис для анализа нескольких визуальных референсов, выбора их характеристик и формирования редактируемого дизайн-брифа.

## 2. Пользователь

Пользователь — человек, которому необходимо сформировать визуальное направление для своего проекта на основе нескольких изображений.

Регистрация и авторизация для MVP не требуются.

## 3. Основной пользовательский сценарий

1. Пользователь открывает главную страницу.
2. Загружает несколько изображений.
3. Сервис проверяет загруженные файлы.
4. Пользователь запускает анализ.
5. Сервис показывает результаты анализа каждого изображения.
6. Сервис показывает сходства и различия между референсами.
7. Пользователь выбирает интересующие его характеристики.
8. Сервис формирует дизайн-бриф на основе выбранных характеристик.
9. Пользователь редактирует текст брифа.

Экспорт брифа рассматривается как дополнительная функция и будет реализован, если останется время.

## 4. Функциональные требования

### FR-01. Загрузка изображений

- Пользователь может выбрать несколько изображений.
- Интерфейс показывает список выбранных файлов.
- Пользователь может удалить изображение из списка до запуска анализа.

### FR-02. Проверка файлов

- Сервис принимает только поддерживаемые форматы изображений.
- Сервис проверяет размер файлов.
- При ошибке пользователь получает понятное сообщение.
- Некорректные файлы не должны приводить к аварийному завершению приложения.

Допустимые форматы и ограничения размера необходимо определить перед реализацией.

### FR-03. Анализ референсов

Для каждого изображения сервис должен по возможности определять:

- основные цвета;
- визуальный стиль;
- характер композиции;
- настроение и атмосферу;
- заметные графические особенности.

Анализ выполняется с помощью выбранной ИИ-модели. Возможности модели необходимо проверить до реализации.

### FR-04. Сравнение референсов

Сервис должен показывать общие и отличающиеся характеристики загруженных изображений.

Результаты должны быть представлены в понятном виде, например в виде отдельных списков сходств и различий.

### FR-05. Выбор характеристик

Пользователь может выбрать характеристики, которые хочет использовать в своём проекте.

Выбор должен влиять на содержание итогового дизайн-брифа.

### FR-06. Формирование дизайн-брифа

Сервис формирует структурированный текст на основе выбранных пользователем характеристик.

Предварительная структура брифа:

- визуальное направление;
- цветовая палитра;
- композиция;
- стиль и настроение;
- рекомендуемые визуальные приёмы.

Пользователь может редактировать полученный текст.

## 5. Нефункциональные требования

- Интерфейс должен быть понятным без инструкции.
- Основной сценарий должен работать в современном браузере.
- Интерфейс должен оставаться удобным на узких экранах.
- Ошибки загрузки и анализа должны отображаться понятными сообщениями.
- Секретные ключи API нельзя хранить в клиентском JavaScript или публиковать в GitHub.

## 6. Обработка ошибок

Предусмотреть сообщения для следующих ситуаций:

- файл имеет неподдерживаемый формат;
- размер файла превышает ограничение;
- изображение не удалось прочитать;
- ИИ-анализ завершился ошибкой;
- для анализа недостаточно изображений;
- не удалось сформировать дизайн-бриф.

## 7. Критерии приёмки MVP

- Пользователь может загрузить несколько поддерживаемых изображений.
- Некорректные файлы обрабатываются без аварийного завершения.
- Сервис выдаёт анализ изображений.
- Пользователь может увидеть сходства и различия между референсами.
- Пользователь может выбрать характеристики.
- Итоговый бриф формируется с учётом выбора пользователя.
- Текст брифа можно редактировать.
- Основной сценарий проверен по тестовым сценариям.

## 8. Ограничения MVP

В первую версию не входят:

- регистрация и авторизация;
- совместная работа;
- облачная история проектов;
- генерация изображений;
- сложная система шаблонов;
- платёжная система.

## 9. Открытые вопросы

- Какую ИИ-модель использовать для анализа изображений?
- Доступна ли выбранная модель в текущем окружении?
- Каковы ограничения количества и размера изображений?
- В каком формате будет экспортироваться бриф, если экспорт войдёт в MVP?
- Какие характеристики анализа действительно нужны пользователям?

Эти вопросы необходимо уточнить до реализации соответствующих функций.
