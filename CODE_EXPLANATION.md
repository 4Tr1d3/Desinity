# Designity — объяснение интеграции и кода

Документ объясняет, как теперь соединены сайт и ИИ. Существующие имена файлов и их основные роли сохранены. Добавлены только инфраструктурные файлы для Docker и документация.

## 1. Общая схема

```text
Браузер
  |
  | GET / и /create-project.html
  | GET /css, /js, /assets
  v
Flask (example_app.py)
  |
  | POST /api/analyze
  v
Blueprint (backend/api.py)
  |
  | analyze_references(images, description)
  v
AI service (backend/ai_service.py)
  |
  | Google Gemini API
  v
JSON с результатами
  |
  v
JavaScript отображает результаты на странице
```

В Docker запускается один Flask-сервис. Он одновременно отдаёт HTML/CSS/JS/изображения и принимает API-запросы. Поэтому frontend обращается к `/api/analyze` на том же домене: отдельный CORS-сервер и второй контейнер не нужны.

## 2. Файлы backend

### `example_app.py` — точка входа Flask

Главная роль файла не изменилась: создать Flask-приложение и подключить API.

Что делает теперь:

- `load_dotenv()` загружает локальные переменные окружения при запуске вне Docker. В Docker переменные передаёт Compose.
- `BASE_DIR` и `FRONTEND_DIR` вычисляют пути относительно самого Python-файла. Это надёжнее, чем зависеть от текущей папки терминала.
- `app.register_blueprint(ai_bp)` подключает endpoint из `backend/api.py`.
- `/` возвращает `frontend/html/main.html`.
- `/create-project` и `/create-project.html` возвращают страницу создания проекта.
- `/css/...`, `/js/...`, `/assets/...` отдают статические файлы из frontend.
- `/api/health` позволяет проверить, что Flask запущен.
- Обработчик 413 возвращает JSON, если запрос слишком большой.

Важно: Flask слушает `0.0.0.0`, а не `127.0.0.1`. Внутри контейнера это необходимо, чтобы Docker мог опубликовать порт наружу.

### `backend/api.py` — HTTP API

Blueprint содержит маршрут:

```python
@ai_bp.post("/api/analyze")
def analyze():
```

Он получает `multipart/form-data`:

- `images` — повторяющееся поле с файлами;
- `description` — необязательное описание задачи.

Далее API читает байты файлов и передаёт список пар `(имя файла, байты)` в `analyze_references()`.

При успехе клиент получает:

```json
{
  "success": true,
  "data": {
    "summary": "...",
    "images_analysis": [],
    "common_features": [],
    "differences": [],
    "color_palette": [],
    "design_brief": {}
  }
}
```

Если обработка не удалась, возвращается `success: false` и поле `error` с сообщением для пользователя.

### `backend/ai_service.py` — работа с Gemini

Это основной ИИ-модуль. Его задача сохранена: подготовить изображения, отправить мультимодальный запрос Gemini и разобрать JSON-ответ.

Основные части:

- `_prepare_image()` проверяет пустой файл, размер и формат. Допустимы JPEG, PNG и WEBP. Затем Pillow приводит изображение к RGB и сохраняет его как JPEG.
- `_extract_json()` извлекает JSON из ответа модели. Дополнительно умеет убрать Markdown-обёртку с тройными обратными кавычками.
- `analyze_references()` проверяет количество изображений (от 2 до 10), наличие `GEMINI_API_KEY`, формирует инструкцию для модели и добавляет в запрос каждое изображение.
- `GEMINI_MODEL` задаёт модель через окружение. Если переменная отсутствует, используется значение по умолчанию, заданное в коде.
- При ошибках API или некорректном ответе выбрасывается `ReferenceAnalysisError`, который перехватывает HTTP-слой.

ИИ не получает ключ из браузера. Ключ остаётся на стороне backend.

## 3. Файлы frontend

### `frontend/html/main.html`

Главная страница. Её структура и назначение не менялись. Ссылка «Создать проект» ведёт на `create-project.html`, который теперь обслуживается Flask.

### `frontend/html/create-project.html`

Страница загрузки референсов. Существующие блоки и их назначение сохранены.

Добавлены:
- поле необязательного описания проекта `#project-description`;
- контейнер `#selected-files` для списка загруженных изображений и удаления файлов;
- контейнер `#results`, в который JavaScript вставляет результаты ИИ.

Названия существующих файлов не менялись.

### `frontend/js/create-project.js`

Теперь это связующее звено между интерфейсом и API.

Основные функции:

- `addFiles()` проверяет тип и размер, не позволяет добавить больше 10 изображений.
- `syncInputFiles()` синхронизирует внутренний список файлов с HTML input.
- `renderSelectedFiles()` показывает выбранные файлы и кнопки удаления.
- `runAnalysis()` собирает `FormData`, добавляет изображения и описание, отправляет `fetch("/api/analyze")`.
- `renderAnalysis()` отображает общее описание, индивидуальный анализ, сходства, различия и цветовую палитру.
- `renderBrief()` собирает дизайн-бриф из результата Gemini и отмеченных характеристик. Текст помещается в textarea, поэтому пользователь может его редактировать.
- Кнопка копирования переносит отредактированный текст в буфер обмена.

Для текста из ответа ИИ используется `textContent`, а не вставка HTML-строк. Это не позволяет интерпретировать полученный текст как HTML-разметку.

### `frontend/css/create-project.css`

Существующие стили страницы сохранены. В конец файла добавлены стили для:
- поля описания проекта;
- списка выбранных изображений;
- карточек анализа;
- сравнительных блоков;
- цветовой палитры;
- выбора характеристик;
- редактируемого дизайн-брифа;
- адаптивного отображения результатов.

### `frontend/js/script.js`, `frontend/css/main.css`

Существующая логика меню и оформление главной страницы не менялись.

## 4. Новые файлы Docker

### `Dockerfile`

Описывает сборку образа:

1. Используется официальный Python 3.12 slim.
2. Копируется `requirements.txt`.
3. Устанавливаются Python-зависимости.
4. Копируется код проекта.
5. Запускается Gunicorn, который обслуживает Flask на `0.0.0.0:5000`.

### `compose.yaml`

Описывает контейнер Designity:
- собирает образ из текущей папки;
- публикует порт хоста 5000 на порт контейнера 5000;
- передаёт переменные из `.env`;
- задаёт `GEMINI_MODEL`;
- автоматически перезапускает контейнер после сбоя.

### `requirements.txt`

Список Python-зависимостей:
- Flask — веб-сервер и API;
- google-genai — официальный клиент Google Gemini;
- Pillow — чтение и преобразование изображений;
- python-dotenv — загрузка `.env` при локальном запуске;
- gunicorn — production WSGI-сервер для Docker.

### `.dockerignore`

Исключает `.git`, виртуальное окружение, кэш Python и секретный `.env` из Docker build context.

### `.env.example`

Шаблон переменных окружения. Его копируют в `.env` и добавляют свой API-ключ. Сам `.env` не хранится в архиве и не должен попадать в Git.

## 5. Что происходит при нажатии кнопки

1. JavaScript проверяет, что выбрано не менее двух изображений.
2. Создаётся `FormData`.
3. Каждый файл добавляется в поле `images`.
4. Текст из поля описания добавляется в `description`.
5. `fetch()` отправляет POST-запрос на `/api/analyze`.
6. Flask принимает запрос и передаёт изображения в AI service.
7. AI service проверяет и подготавливает изображения.
8. Gemini получает текстовую инструкцию и изображения.
9. Ответ Gemini разбирается как JSON.
10. Flask возвращает JSON в браузер.
11. JavaScript строит блоки результатов.
12. Пользователь отмечает нужные характеристики и формирует редактируемый бриф.

## 6. Что важно проверить на первом запуске

Docker-часть и frontend/backend-интеграция подготовлены, но реальный ответ Gemini зависит от действующего ключа, доступности модели и сетевого доступа контейнера к Google API. Поэтому первый полноценный тест нужно сделать с реальным `GEMINI_API_KEY`.

Если модель вернёт структуру, отличающуюся от ожидаемой, нужно будет адаптировать отображение к фактическому JSON, не меняя общую архитектуру.
