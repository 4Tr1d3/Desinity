# Паспорт проекта Designity

## 1. Название проекта
Designity

**Слоган:** Analyze. Combine. Create.

## 2. Команда проекта
- **Стребков Даниил** — тимлид и frontend-разработчик. Координирует работу команды, отвечает за пользовательский интерфейс, интеграцию frontend-части и согласование требований.
- **Ольхов Александр** — backend-разработчик. Отвечает за серверную логику, обработку данных и интеграцию AI-функций.
- **Тахтаров Александр** — DevOps и тестировщик. Отвечает за настройку окружения, запуск проекта, проверку работоспособности и тестирование.

Команда совместно участвует в обсуждении требований, проверке результата и подготовке итоговой презентации.

## 3. Целевая аудитория
Люди, которые создают визуальный контент: начинающие дизайнеры, студенты, авторы презентаций и другие пользователи, которым нужно определить визуальное направление проекта.

## 4. Проблема
При подготовке визуального проекта пользователю бывает сложно сравнить несколько референсов, выделить подходящие характеристики и объединить их в целостную концепцию.

*Статус: предварительная гипотеза, требует проверки интервью.*

## 5. Как пользователи решают проблему сейчас
Предположительно, пользователи самостоятельно ищут изображения, сохраняют их в подборки, сравнивают визуальные характеристики и вручную формулируют идею будущего дизайна.

*Статус: проверить на интервью.*

## 6. Гипотеза проекта
Если предоставить пользователю инструмент для анализа и сравнения нескольких визуальных референсов с возможностью самостоятельно выбирать характеристики, ему будет проще сформировать целостное визуальное направление и подготовить дизайн-бриф.

## 7. Путь пользователя
1. Пользователь открывает Designity.
2. Загружает несколько визуальных референсов.
3. Получает результаты ИИ-анализа.
4. Изучает сходства и различия изображений.
5. Выбирает характеристики для будущего дизайна.
6. Формирует и редактирует дизайн-бриф.
7. Экспортирует результат.

## 8. Три основные функции MVP
1. Загрузка и проверка нескольких изображений.
2. ИИ-анализ референсов, включая сходства, различия и визуальные характеристики.
3. Формирование редактируемого дизайн-брифа на основе выбранных пользователем характеристик.

## 9. Что откладываем
- Регистрацию и авторизацию пользователей.
- Совместную работу над проектами.
- Сложную историю проектов и облачное хранение.
- Генерацию готовых изображений.
- Дополнительные режимы анализа, не необходимые для основного сценария.

## 10. Данные для прототипа
- Набор тестовых изображений без персональных данных.
- Примеры визуальных референсов с различающимися стилями.
- Тестовые сценарии и ожидаемые результаты.

## 11. Проверка проекта
Будут подготовлены минимум пять сценариев проверки: корректная загрузка изображений, обработка некорректного ввода, получение анализа, выбор характеристик и формирование итогового брифа.

## 12. Как измерим пользу
Предварительные критерии:
- Пользователь может самостоятельно пройти основной сценарий.
- Результат анализа понятен пользователю.
- Пользователь может выбрать характеристики и получить пригодный для дальнейшей работы бриф.
- Во время тестирования фиксируются затруднения, ошибки и предложения.

Конкретные критерии и пороговые значения будут уточнены после интервью.

## 13. Почему пользователь может вернуться
Предположение: сервис может быть полезен при подготовке новых визуальных проектов, когда необходимо сравнить референсы и сформировать новое дизайн-направление.

## 14. Возможная поддержка проекта
Предположение: сервис может быть полезен начинающим дизайнерам, студентам и небольшим творческим командам. Возможные способы поддержки или монетизации будут рассмотрены позднее.

## 15. ИИ-агенты и инструменты
- Аналитик: помогает формализовать требования.
- Разработчик: помогает реализовать прототип по согласованным требованиям.
- Проверяющий: анализирует требования и результаты тестирования.
- Собственный Skill: инструкции для повторяемых задач агента.
- MCP: подключение к внешнему инструменту для получения и проверки информации.

Фактически использованные агенты, навыки и MCP будут зафиксированы в журнале работы.

## 16. План работ
- Неделя 1: уточнение проблемы, интервью, паспорт проекта, требования и интерфейс.
- Неделя 2: настройка окружения и ИИ-инструментов, реализация основного сценария.
- Неделя 3: тестирование с пользователями, исправления, документация и защита.

## 17. Если времени будет недостаточно
Сохранить основной сценарий: загрузка референсов → анализ → выбор характеристик → формирование брифа. Второстепенные функции исключить.
